# Architecture

Kurarium is a Windows desktop application with three main processes/areas:

- **Electron shell** (`electron/`): tray integration, window lifecycle, auto-start,
  local URL selection, and certificate pinning for the embedded window.
- **Backend** (`backend/`): Fastify HTTP/HTTPS server, SQLite databases, media
  scanning, thumbnails, SMB mounting, authentication, and transcoding.
- **Frontend** (`frontend/`): React UI served by the backend in production, or by
  Vite during development.

## Startup

1. Electron resolves the data directory (installed, portable, or development).
2. It sets `MEDIAVIEWER_DATA_DIR`, `KURARIUM_VERSION`, and (when packaged) the bundled
   web and FFmpeg paths.
3. The backend loads `data/.system/config.ini`.
4. If LAN publishing is enabled, the backend generates or loads the self-signed TLS
   certificate and starts Fastify with HTTPS. Otherwise it listens on loopback HTTP.
5. Electron loads the local URL. For HTTPS, it accepts only the certificate whose
   fingerprint matches the certificate generated by its own backend.

## Data

- `mediaviewer.db`: media items, libraries, SMB connections, tags, history, sessions,
  and application metadata.
- `thumbs.db`: thumbnail blobs with LRU/TTL metadata.
- `transcoded/`: temporary transcoded video outputs.
- `.system/config.ini`: server settings and password hash.
- `.system/tls/`: LAN certificate and private key.

The database is the source of truth for scanned media. Original media files are never
modified.

## Security boundaries

- Loopback mode is unauthenticated by design; any process in the same Windows user
  session can call the API.
- LAN mode requires a login and HTTPS. Every authenticated client has the same
  access level.
- Host and Origin validation, CSP, and cross-site request checks protect the local
  API from browser-based attacks.
- SMB credentials are stored in Windows Credential Manager. LAN passwords are stored
  as scrypt hashes.
- The self-signed LAN certificate is not a Windows code-signing certificate.

## Release flow

`npm run build` builds the backend, frontend, and Electron entry points. `npm run dist`
packages the NSIS installer and portable ZIP. The GitHub Actions release workflow
also prepares checksums, legal notices, FFmpeg corresponding source, an SBOM, and (for
public repositories) build provenance attestations.
